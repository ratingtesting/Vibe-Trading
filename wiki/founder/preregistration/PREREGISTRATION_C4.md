# ПРЕДРЕГИСТРАЦИЯ C4 — гейт режима (тренд / боковик / хаос) для стратегий

Дата: 2026-10-16. Фаза: C4 (PLAN_V5 §2). Фиксируется ДО прогона.

## Зачем (гипотеза, объясняющая две наши неудачи одним механизмом)

Два измеренных факта требуют объяснения:
- C1 (парный арбитраж): грязная доходность ≈ 0 — возврат к среднему **не работает** на часовом горизонте.
- C2 (Clenow): на DEV сильный (+33%/год, t=3.67), на EVAL почти ноль (+3.9%/год, t=0.43).

Гипотеза одна: **сигналы усредняются до нуля, потому что работают в РАЗНЫХ режимах**. Трендовые
стратегии кормятся трендами, возвратные — боковиком; смешение режимов даёт «в среднем ноль».
Если гипотеза верна, гейт режима должен улучшить СВЕЖИЕ данные (EVAL) у трендового сигнала и способен
оживить убыточный возвратный сигнал, не трогая DEV-числа стратегии как таковой.

## Определение режима (механическое, фиксируется здесь; вычисляется по BTCUSDT как рыночному прокси)

Ежедневно, по дневным барам:
1. Наклон регрессии лог-цены за **50 дней** → годовая ставка `slope50`, и R² регрессии.
2. Волатильность: `vol20` (стд. дневных лог-доходностей за 20 дней) и `vol60`.
3. **TREND** = |slope50| > 15%/год И R² > 0.50.
4. **RANGE** = |slope50| ≤ 15%/год И vol20 ≤ 1.2 × vol60.
5. Иначе — **CHAOS**.

Пороги выбраны до прогона из соображений смысла (15%/год — граница «заметный тренд» для крипты,
R² 0.5 — «половина движения объясняется линией»), не подгонкой. Скрипт печатает долю дней каждого
режима по половинам DEV/EVAL — это проверка, что режим не вырожден (ноль дней в режиме = дефект).

## Эксперимент (A/B, две руки, заявлены заранее)

- Рука A: стратегия Clenow-моментум на крипте (R²≥0.8, топ-10, ATR-размер, недельный ребаланс) —
  **без гейта** (это уже измеренный C2: DEV t=3.67, EVAL t=0.43).
- Рука B: та же стратегия, но вход разрешён **только при TREND**, и при выходе из TREND книга
  закрывается полностью.

Гейт режима применяется к стратегии, а не наоборот: режим вычисляется ТОЛЬКО по прошлым данным
(строгая каузальность; проверяется тестом — порча будущих баров не меняет метку сегодняшнего дня).

## Гейты вердикта

| Гейт | Порог |
|---|---|
| G1 (главный) | EVAL руки B: t ≥ 2.0 И средняя > 0 (улучшение свежих данных) |
| G2 | DEV руки B остаётся положительным (гейт не убивает сигнал) |
| G3 | доля дней TREND и RANGE в обеих половинах ≥ 5% (режим не вырожден) |
| G4 | каузальность: тест «порча будущего» проходит |
| G5 | издержки ×2: EVAL остаётся положительным |

**Вердикт:** все G1-G5 → «гейт режима полезен, внедряем в движок»; G3 не взят → дефект классификатора,
прогон недействителен; G1 не взят → гипотеза «режимы объясняют провал» не подтверждена — фиксируем
это честно и НЕ подбираем пороги режима после результата.
